# Эксплуатация ХозУчёт

## Среды и секреты

Dev, test и production используют отдельные базы и файлы. Секретный ключ Django, пароль PostgreSQL и пароль первого администратора передаются через переменные окружения и не записываются в репозиторий. В production обязательны `DJANGO_DEBUG=false`, `DJANGO_SECURE=true`, HTTPS и точный список `DJANGO_ALLOWED_HOSTS`.

## Первый запуск

1. Поднять PostgreSQL и web-контейнер: `docker compose up -d --build`.
2. Дождаться состояния healthy: `docker compose ps`.
3. Открыть `/api/v1/health/` и `/api/v1/docs/`.
4. Войти WPF-клиентом под учётной записью из `HOZUCHET_ADMIN_USERNAME`.
5. Выполнить `docker compose exec web python manage.py verify_ledgers`.

`entrypoint.sh` применяет миграции, собирает static и идемпотентно создаёт администратора, когда заданы обе переменные `HOZUCHET_ADMIN_USERNAME` и `HOZUCHET_ADMIN_PASSWORD`.

## Резервные копии

Ежедневно запускается `tools/backup.ps1`. В копию входят PostgreSQL в custom dump и том `media`. Копии хранятся вне сервера приложения. Рекомендуется хранить не менее 14 ежедневных и 3 месячных копий.

Раз в месяц выполняется тестовое восстановление в чистой среде:

1. Поднять пустой комплект контейнеров.
2. Запустить `tools/restore.ps1` с парой dump/tar одного времени.
3. Убедиться, что команда сверки завершилась успешно.
4. Сверить количество документов, остатки, партии и сальдо контрольных контрагентов.
5. Запустить smoke-test WPF-клиента.

## Обновление

Перед обновлением создать резервную копию. Затем собрать новый image, применить миграции и проверить health/OpenAPI/ledger. При ошибке приложение не должно запускаться поверх частично применённой бизнес-операции: проведение выполняется в `transaction.atomic`, а повтор использует тот же `Idempotency-Key`.

## Мониторинг

Контролируются health endpoint, доступность PostgreSQL, свободное место для БД/media/backup, HTTP 5xx и журнал аудита. Ошибку пользователя связывают с документом, actor и request id. Проведённые документы не редактируются вручную в БД.

## Клиент

Self-contained Windows x64 пакет создаётся `tools/publish-windows.ps1`. Адрес сервера задаётся переменной `HOZUCHET_API_URL`. Для удалённого сервера разрешён только HTTPS. Пароль хранится в памяти процесса на время сеанса и не записывается в файл клиента.
