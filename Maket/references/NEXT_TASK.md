# Следующая задача — программа ХозУчёт (Tauri + сервер)

Дата фиксации: 09.10.2026. Решения: [ADR-0002](adr/0002-sync-feed.md) (лента изменений, этапы заказа), [ADR-0003](adr/0003-tauri-offline-client.md) (Tauri, локальная копия, очередь).

## Сделано

- Сервер: лента изменений `/sync/changes`, этапы заказа (новый → собираем → отправлен → доставлен), оплата при проведении продажи/прихода/доставки заказа (наличные, МБанк, остаток в долг), номера документов от сервера, идентификаторы от клиента, вход по токену, CORS, категории и загрузка фото товаров. Тесты: `backend\.venv\Scripts\python.exe backend\manage.py test apps`.
- Макет и программа: касса (продажа, приход, заказы-канбан, люди и долги), режим сервера (`js/server.js`): вход, мгновенная локальная работа, очередь отправки, догрузка при появлении связи, уведомления о заказах других пользователей.
- Оболочка Tauri: `app/`, сборка `cd app && npm run build:exe` (результат `app/src-tauri/target/release/hozuchet.exe`).
- Каталог Otabek: backend синхронизирует базовый товар и его размеры как отдельные позиции каталога; касса показывает одну карточку товара, затем быстрый выбор размера. Для этих позиций не ведётся проверка наличия, партий и FIFO: количество в продаже — только количество строки. Кнопка «Новый товар» открывает `https://otabek.glasscenter.kg/add`. Для синхронизации серверу нужны `OTABEK_USERNAME` и `OTABEK_PASSWORD`.
- 22.10.2026: касса и заказы используют пакетный набор: товар → таблица всех размеров с количеством и суммой → одно добавление в документ. Повторное открытие редактирует итоговые количества; 0 убирает размер, цены и скидки сохраняются. Enter/↑/↓ перемещают между полями, Ctrl+Enter применяет. Проверки: `node tests/variant-quantities.test.js`, `node tests/engine.test.js`, проверка на реальном каталоге в браузере.
