# Инвентаризация проектов ХозУчёт

Дата проверки: 28.10.2026.

## Резюме

В репозитории находится один продукт «ХозУчёт», разделённый на четыре технических контура: Django API, браузерный интерфейс, Windows-оболочка Tauri и отдельный WPF-клиент. Серверная бизнес-логика и тесты находятся в хорошем рабочем состоянии. Главный организационный риск — одновременно развиваются два Windows-клиента, а документация по-прежнему называет основным то WPF, то Tauri.

Текущее состояние нельзя считать релизным: в `main` накоплено 86 незакоммиченных позиций, актуальная Tauri-сборка заблокирована занятым каталогом `app/web`, установщик отсутствует, а проверка конкурентных сценариев на PostgreSQL ещё не закрыта.

## Backend-модули

В `backend/apps/` присутствуют следующие предметные модули:

- `access` — пользователи, роли и доступ к складам;
- `catalog` — товары, категории, цены, фото и интеграция Otabek;
- `warehouses` — склады;
- `documents` — продажи, поступления, заказы и возвраты;
- `inventory` — партии, движения, остатки, FIFO и резервы;
- `payments` — платежи;
- `settlements` — обязательства, распределения и взаимозачёт;
- `partners` — контрагенты;
- `imports` — двухшаговый Excel-импорт;
- `reporting` — отчёты;
- `audit` — аудит;
- `sync` — лента изменений для offline-клиента.

Среда backend использует локальный Python 3.13.14. Для production предусмотрены Gunicorn, WhiteNoise и PostgreSQL; SQLite используется в быстрых локальных тестах.

## Основные риски

1. **Нет однозначного клиентского направления.** README называет рабочей версией WPF, а `NEXT_TASK.md` — Tauri. Поддержка двух UI увеличивает объём реализации и тестирования.
2. **Слишком большой незакоммиченный срез.** Backend, UI, тесты, документация и миграция Otabek смешаны в одном рабочем дереве; восстановление и ревью затруднены.
3. **Нет воспроизводимого актуального установщика.** Логика проходит тесты, но Tauri web bundle сейчас не пересобирается, а WPF release archive отсутствует.
4. **Не закрыта production-конкурентность.** SQLite-тесты успешны, но критичные гонки должны быть проверены на PostgreSQL.
5. **Документация отстаёт от кода.** Формальный план показывает только 2 завершённые задачи, хотя реализована почти вся предметная модель.

## Рекомендуемый порядок действий

1. Определить основной Windows-клиент: Tauri или WPF; второй явно пометить как legacy, эталон либо отдельный поддерживаемый продукт.
2. Разделить текущие изменения на проверяемые коммиты: Otabek/backend, UI-прототип, Tauri/offline, тесты и документация.
3. Освободить `app/web`, повторить `npm run web`, затем собрать `npm run build` и проверить установщик на чистой Windows.
4. Поднять PostgreSQL и закрыть конкурентные тесты и rehearsal backup/restore.
5. Исправить два предупреждения OpenAPI и сохранить актуальную схему.
6. Актуализировать `TASKS.md`, `README.md` и `NEXT_TASK.md` после выбора клиента и релизной проверки.
