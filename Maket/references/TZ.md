## Состояния

Учётные документы: DRAFT → POSTED → REVERSED. Из REVERSED повторное проведение запрещено; исправление — копия нового черновика со ссылкой. DRAFT допускает редактирование/удаление с аудитом. POSTED неизменяем. Возвраты и платежи имеют те же состояния. При зависимостях отмена запрещается до отмены зависимых операций в обратном порядке; история не стирается.
Заказ: DRAFT → ASSEMBLING → ASSEMBLED → DONE; ASSEMBLED → ASSEMBLING; активный → DRAFT/CANCELLED; DONE только после связанной продажи. Отмена этой продажи возвращает заказ в ASSEMBLED и восстанавливает резерв только при наличии товара (в одной транзакции). Одновременно не более одной действующей продажи заказа.

## Сценарии операций

Общее для OP-001…OP-010: вход содержит UUID, version, склад (для товара), idempotency key, автора из сессии. Backend проверяет права, ссылки, статус и точность; блокирует затрагиваемые записи; пишет движения, аудит и результат одной транзакцией. Ошибка откатывает всё; черновик остаётся доступным. Коды ошибок определены в ARCHITECTURE.md.

### OP-001 Начальные остатки (REQ-004,005,017)
Вход: склад, товар, положительное количество, стоимость единицы, дата, причина. Проверки: доступ, активный товар, допустимая единица, отсутствие повторного пакета. Действия: создать партию и приход, без расчётного движения. Результат: остаток/стоимость увеличились, сальдо прежнее. Нулевая стоимость допустима только явно; роль автора не определяет тип операции. Не использовать этот документ вместо закупки.

### OP-002 Закупка (REQ-006,007)
Вход: контрагент, склад, строки, цены, допрасходы; связанная оплата опциональна. Проверки: строки непустые, количество >0, цена ≥0, расходы ≥0, итог распределён точно. Действия: расчёт → партии → складской приход → отрицательное расчётное начисление → отдельный платёж → согласованный взаимозачёт. Обязательство включает закупку, но не расходы перевозчика (учёт перевозчика вне объёма). Ошибка распределения/платежа в объединённой команде откатывает весь пакет.

### OP-003 Продажа (REQ-008,009,012,017)
Вход: склад, контрагент, строки с ценой/скидкой, заказ при наличии, тип цены, связанная оплата. Повторяющиеся товары суммируются при проверке доступности. Проверки: скидка ≤ суммы строки, цена/количество допустимы, резерв чужих заказов исключён, версия актуальна. Действия: фактические суммы → FIFO → складской расход → положительное начисление всей продажи → отдельный платёж → зачёт. Нехватка возвращает товар/остаток/резерв/недостающее; быстрый приход сохраняет черновик. Последнюю единицу продаёт один клиент. Полностью бесплатная строка имеет количество/себестоимость, но нулевое начисление.

### OP-004 Платёж (REQ-010,013)
Вход: контрагент, направление, сумма >0, распределение по открытым обязательствам, основание. Проверки: сумма распределений равна платежу, обязательства принадлежат этому контрагенту и стороне, переплаты нет. Получение уменьшает положительное сальдо; выдача увеличивает его. Никаких товарных движений/выручки. Частичная оплата допустима конкретному клиенту. Платёж можно провести отдельно; комбинированная команда имеет два документа и общий откат.

### OP-005 Возврат покупателя (REQ-011)
Вход: продажа, исходные строки, количества, склад возврата, причина. Проверки: продажа проведена, не отменена, общий возврат не больше проданного; против параллельных возвратов блокировка исходной строки. Цена — фактическая после всех скидок. Действия: восстановить товар/стоимость → отрицательное расчётное движение на полную сумму возврата → распределить уменьшение исходного долга; оплаченная часть становится обязательством выдать деньги. Возврат сам не платит деньги. Последняя часть возвращает точный остаток стоимости/суммы; нулевая цена не вызывает деление на ноль.

### OP-006 Заказ (REQ-012,019)
Вход: клиент, склад, строки, комментарий. Подтверждение проверяет свободный товар и создаёт резерв. Редактирование активного заказа проверяет только дельту с исключением собственного резерва. Сборка сохраняет резерв; печать ничего не проводит. Продажа атомарно списывает товар и закрывает резерв/заказ. Отмена/возврат в черновик освобождает резерв. Не резервировать партии заранее.

### OP-007 Возврат поставщику и смешанное погашение (REQ-015)
Вход: исходная закупка/обязательство, склад, количества, денежные распределения. Проверки: товар получен по источнику, ранее не возвращён, свободен от чужого резерва; денежные долги без товарного источника гасятся только деньгами. Действия: сначала доступные единицы исходной партии, далее FIFO (Q-006) → расход стоимости → положительное расчётное движение по договорной цене закупки → отдельный исходящий платёж. Для долга покупателя товарная часть выполняет OP-005. Несовпадение количества и денежного эквивалента показывать явно. Возвращённый товар и денежная оплата не списывают товар дважды.

### OP-008 Взаимозачёт (REQ-014)
Вход: контрагент и документ-причина. Заблокировать открытые обязательства; выбрать минимум встречных сумм; создать документ зачёта и парные распределения. Сальдо остаётся прежним, открытые стороны сокращаются одинаково. Без встречного долга результат — нет зачёта. Повтор не повторяет распределения. Пример: продажа +10000, закупка −4000 → сальдо +6000; зачёт 4000 не меняет +6000; получение 6000 →0, все три документа сохранены.

### OP-009 Отмена (REQ-016)
Вход: документ, версия, причина. Проверки: проведён, право отмены, нет действующих возвратов/платежей/зачётов/расхода партии, мешающих точному сторно. Создать противоположные движения со ссылками на оригинал, отменить распределения компенсирующими записями, отметить REVERSED. Не удалять оригинал. Если восстановленный резерв недопустим — отказ всей операции. Повтор возвращает первоначальный результат.

### OP-010 Импорт (REQ-018)
Вход: Excel (товары, контрагенты, остатки, долги), склад, ключ пакета. Сначала полный разбор/валидация и предпросмотр без движений, затем подтверждение того же checksum. Проверки: дубли кодов, единицы, числа, ссылки, лимит файла, повтор контрольной суммы. Одной транзакцией создаёт справочники, партии, начальные расчётные движения и аудит. Долги без надёжного источника стоимости возвращаются только деньгами. Файл с одной ошибкой ничего не применяет. Старый localStorage не импортируется автоматически.
