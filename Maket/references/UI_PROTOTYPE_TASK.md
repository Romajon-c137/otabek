# UI-прототип без складского учёта

Запрос 25.10.2026: довести UI и все ранее перечисленные сценарии на тестовых операциях; не переделывать боевой backend. Только продажи, деньги, взаимные долги, заказы как оформление продажи. Нет наличия, партий, FIFO, складских резервов.

## Изоляция

- Новый режим `index.html?ui=1`, отдельный ключ `hozuchet-ui-prototype-v1` и отдельная тестовая очередь. `Server.boot()` в нём не вызывается.
- Копируются только товары из локального кэша реального каталога; продажи и люди — тестовые. Обновление каталога допускает только GET и все страницы.
- Основной URL с `?server=...` и рабочая БД должны остаться нетронутыми. Не проводить реальные финансовые операции при browser QA.
- Никаких мобильных файлов/сборок. Не создавать подагентов без разрешения пользователя.

## План приёмки

1. Модель: продажи без наличия, скидки/цены, сводка по датам Asia/Bishkek, оба направления долга, погашения/зачёт, возврат, отмена/исправление, черновики, тестовая очередь и повтор без дублей.
2. Главная: показатели дня, все черновики; новый отчёт за период: кому продали, как оплатили, кто должен.
3. Проведённый документ, результат оплаты, накладная/лист сборки, копирование и исправление продажи.
4. Люди: поиск/создание/карточка/история/запись долга/погашение/взаимозачёт.
5. Возвраты: товар → размеры, количество, уменьшение долга/выдача денег, повторный возврат не превышает проданное.
6. Заказы: сохранение без резерва, статусы, редакция, доставка → оплата, отмена.
7. Каталог: группы и размеры, цены, фото, архив; без склада. Две цены можно задать локально, импорт не выдумывает оптовую цену.
8. Тестовый вход, панель и очередь: имитация offline/ошибки, повтор, открытие/исправление операции, сохранение при перезапуске.
9. Проверки: node tests/*.test.js; синтаксис; web build; browser QA только изолированного режима; длинная накладная/печатный preview; не печатать физически.

## Текущий результат

- Реализованы главная со сводкой дня, отчёт за период и покупателям, документы, люди/оба направления долга, погашения, явный взаимозачёт, возвраты, исправление/отмена продажи, повтор продажи, все черновики.
- Заказы: новые → в работе → отправлены → оплата; отмена, накладная и лист сборки. Никаких проверок наличия или резервов в прототипе.
- Каталог: копия реальных товаров; обновление только GET всех страниц; локальное создание/редактирование размеров и розничных/оптовых цен, архив. Эти изменения не отправляются в Otabek.
- Долг денежный, по чеку целиком. Возврат сначала уменьшает долг этого чека. Встречные долги не зачитываются автоматически.
- Тестовый вход demo/demo, локальная очередь с имитацией offline/ошибки, повтором и исправлением. Оплаты и взаимозачёты можно отменять с причиной; связанные операции защищены от некорректной отмены.
- Режим сохраняется отдельно от рабочей БД. Рабочий backend в рамках этой задачи не переделывался. Это UI-прототип, не готовый производственный учёт.
- Node-наборы прошли. В браузере проверены продажа нескольких размеров, скидка, смешанная оплата/долг, погашение, возврат, исправление, заказ до оплаты, лист сборки, каталог, создание человека/товара, черновик, offline/ошибка/повтор, вход и восстановление после перезагрузки. Предпросмотр накладной на 43 размера без горизонтального обрезания; физическая печать не выполнялась.
- По просьбе пользователя дальнейшие тестовые прогоны остановлены; следующий этап — его визуальные поправки. Данные QA находятся только в тестовом контуре.

## Известные нюансы инструментов

- Старое backend/.venv указывает на удалённый Python 3.13. Для локальных команд использовать bundled Node `C:/Users/Roma/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node.exe`.
- Browser CUA REPL уже инициализирован: browser `iab`. Пользовательские вкладки не перезагружать (могут содержать введённые количества). Создавать временную скрытую вкладку для QA; сохранять полный screenshot и закрывать её.
- `tab.screenshot({clip})` ошибочно смещает следующие клики; пользоваться полным screenshot.
- Много ранее изменённых пользовательских файлов: не откатывать и не чистить нерелевантные изменения.
